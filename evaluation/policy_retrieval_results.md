# 政策检索评测记录

## Baseline

- Embedding：BAAI/bge-small-zh-v1.5
- 向量维度：512
- 向量数据库：PostgreSQL + pgvector 0.8.6
- 数据规模：6 个政策块
- 评测规模：12 条查询
- Hit@1：8/12（66.67%）
- Hit@3：12/12（100.00%）
- MRR：0.8333
- 平均检索耗时：0.0172 秒

失败案例：

- 未发货退款查询被“已发货订单退款申请”排在第一。
- 商品损坏和功能异常查询被“型号或尺寸不合适”排在第一。

## 标题与领域词增强

优化内容：

- 将政策标题和正文共同用于文档向量生成。
- 为未发货场景补充“还没发货、未寄出、等待发货”等表达。
- 为质量问题补充“坏了、按键失灵、没有声音、无法使用”等表达。
- 未更换 Embedding 模型。

评测结果：

- Hit@1：12/12（100.00%）
- Hit@3：12/12（100.00%）
- MRR：1.0000
- 平均检索耗时：0.0162 秒

相对 Baseline：

- Hit@1：66.67% → 100.00%
- MRR：0.8333 → 1.0000

## Holdout 泛化评测

- 评测规模：12 条未参与调优的查询
- Hit@1：7/12（58.33%）
- Hit@3：12/12（100.00%）
- MRR：0.7917
- 平均检索耗时：0.0173 秒

结论：

- 开发集 Hit@1 达到 100%，但 Holdout 仅为 58.33%，说明标题和领域词增强存在明显过拟合。
- 所有目标政策均进入前三，说明向量召回能力尚可，主要问题是第一名排序不稳定。
- 退款场景中的“待发货、已揽件、确认收货”等订单阶段，仅靠文本向量难以稳定区分。
- 质量问题与型号问题仍存在语义混淆，需要进一步排序优化。

## Hybrid Retrieval Holdout 评测

优化方式：

- 使用订单系统返回的 `order_status` 进行结构化过滤。
- 在过滤后的政策集合中使用 pgvector 余弦相似度排序。
- 未更换 Embedding 模型。

结果：

- Hit@1：11/12（91.67%）
- Hit@3：12/12（100.00%）
- MRR：0.9583
- 平均检索耗时：0.0156 秒

相对纯向量 Holdout：

- Hit@1：58.33% → 91.67%
- MRR：0.7917 → 0.9583
- 退款政策查询全部命中第一名。
- 剩余失败集中在退换货质量问题与规格问题的排序。


## Refund Agent RAG 集成评测

- 多智能体案例：8 条
- 任务成功率：100%
- 路由正确率：100%
- 工具调用正确率：100%
- 越权工具调用：0
- 违规回复：0
- 缺少政策依据：0
- 平均响应耗时：5.799 秒
- 总墙钟时间：46.389 秒

结论：

- Refund Agent 已按顺序完成订单验证、Hybrid Retrieval 和退款审核工单创建。
- 最终回复能够引用政策标题和来源。
- 接入 RAG 后正确性保持不变，但平均延迟由 2.417 秒增加至 5.799 秒。
- 首个退款案例包含 Embedding 模型冷启动，后续需要区分冷启动和热请求性能。
